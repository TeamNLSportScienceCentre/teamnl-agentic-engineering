# Wanneer is het af?

## In één zin
Spreek vooraf af wanneer je project (of een feature) af is, zodat "nog even dit erbij" een bewuste keuze wordt in plaats van een gewoonte.

## Waarom
Met een agent kan alles: nog een grafiek, nog een knop, nog een export. Die onrust ("dit kan ik nu ook!") maakt projecten groot, rommelig en nooit klaar. Een duidelijk eindpunt helpt je stoppen, opruimen en overdragen.

## Wanneer wel, wanneer (nog) niet
Bij de start van een project en bij elke nieuwe feature.

## Zo begin je
1. **Kies je fase** (zie de [moeilijkheid](../README.md) in het naslagwerk): prototype, proof of concept, MVP (minimum viable product: de kleinste versie die een echte gebruiker helpt) of productie.
2. **Schrijf een "klaar als"-lijst** in je `plan-van-aanpak.md`, bijvoorbeeld:
   - [ ] De coach kan het weekoverzicht openen zonder mijn hulp
   - [ ] Het werkt op voorbeelddata én bij een collega (README gevolgd)
   - [ ] Er staat geen echte data in git
   - [ ] De belangrijkste berekening is [getest](../repo/testen.md)
3. **Nieuwe ideeën** gaan naar een lijstje "later" (of een [issue](issues-gedreven.md)), niet meteen in de code.
4. **Is het af?** Ruim op, werk de README bij, schrijf een laatste hand-off en commit. Dan pas het volgende.

## Valkuilen
- "Af" betekent niet "perfect". Het betekent: doet wat afgesproken is, en een ander kan ermee verder.
- Doorbouwen zonder op te ruimen: elke laag maakt de vorige moeilijker te begrijpen.
- Voor huiswerk geldt hetzelfde: een kleine werkende versie is meer waard dan een grote halve.
